Worktree creation · implementation report

Faster worktrees, with a terminal that waits for truth.

Orca now overlaps independent creation work, avoids duplicate Git probes, and can optionally reveal a terminal during checkout. The terminal is visible early but cannot run input, agents, setup, or sibling tabs until the checkout and readiness contract is complete.

Creation pipeline

Independent work overlaps; every authority-changing step stays ordered.

The early terminal safety contract

Visible does not mean executable. The checkout gate owns every startup boundary.

Input is swallowed before readiness

The gate disables echo, ignores control signals, and accepts only its random release token.

Startup work cannot jump the queue

Agents, setup, default tabs, trust mutation, and sibling terminals remain blocked.

Shell hooks reload after checkout

The original interactive shell receives startup only after project files exist.

Rollback requires physical-stop proof

Orca keeps the partial worktree when it cannot prove every creation PTY exited.

Cancellation linearizes once

A winning cancellation suppresses every release/startup path; a committed start stays final.

Post-spawn failures retain PTY identity

Even publication failure before provider return reaches bounded exact-PTY teardown.

Accepted experimental gaps

The setting remains off by default while physical and soak evidence accumulates.

Physical Windows, Linux, and WSL journeys; live SSH and an actual old relay; crash-persistent checkout barriers; and a reproducible end-to-end performance benchmark remain uncollected. Cancellation/setup/default-tab/release-failure Electron variants remain unit-covered. These are evidence gaps, not open P0/P1/P2 findings.
